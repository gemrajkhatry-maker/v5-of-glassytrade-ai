# Fabio AMT Strategy Compliance Audit

**Date:** 2026-03-19
**Status:** CRITICAL FINDINGS — System NOT Compliant
**Reviewer:** Senior QA / Strategy Audit

## Executive Summary

The system is **NOT working as per Fabio Valentini's AMT methodology**. While many individual components exist, the **execution flow is broken** — entries are being generated by a probability-based "Signal Coordinator" that bypasses Fabio's core principles.

**Root Cause:** The entry logic was refactored into a `SignalCoordinator` class that uses probability-based conviction instead of the proper Fabio drive/aggression/alignment system. This has created a parallel entry path that conflicts with the original AMT design.

---

## 1. Critical Findings

### 1.1 Entry Logic Is BROKEN ❌❌

**What Fabio Says:**
> "Don't enter until drive 2. The first drive is noise. Wait for the re-test."

**What the System Does:**
The `SignalCoordinator.evaluate_entry()` method checks:
- `agent_prob >= 0.55` → MEDIUM conviction → allow entry
- `agent_prob >= 0.65` → HIGH conviction → allow entry

**But it does NOT check:**
- ❌ Drive number (D1 vs D2)
- ❌ Whether first drive was rejected
- ❌ Momentum fade
- ❌ Three-Align gate properly

**Evidence from `_execute_unified_entry()` in `trading_session.py`:**
```python
# The signal coordinator doesn't use three_align_check properly
# It calls three_align_check but doesn't block on drive_number == 1
# It uses confirmation_strong only as a "nice to have", not a gate
```

### 1.2 Execution Path Is Scatterbrained ❌❌

**What Fabio Says:**
> "One clean pipeline. Tick in → signal out. No threading, no scattered logic."

**What the System Does:**
Entries are triggered from **three different paths**:

1. **Signal Coordinator Path** (`_execute_unified_entry`):
   - Called from `_on_tick()` in `trading_session.py`
   - Uses `SignalCoordinator.evaluate_entry()`
   - Can create signals with simple SL/TP (2% stop, 4% target)

2. **LLM Handler Path** (`_llm_handler.run_entry()`):
   - Runs independently in background thread
   - Can also create signals
   - Sometimes overrides signal coordinator

3. **Engine Path** (`engine.py`):
   - Has a throttle mechanism (500ms)
   - Can trigger process_tick directly

**This means the SAME tick can trigger MULTIPLE entry attempts.**

### 1.3 Stop Loss Is Wrong ❌❌

**What Fabio Says:**
> "SL just beyond the aggressive print cluster + buffer. Never arbitrary percentage."

**What the System Does:**
From `_execute_unified_entry()`:
```python
if is_buy:
    stop_price = tick.close - (tick.close * 0.02)  # 2% stop
    tp_price = tick.close + (tick.close * 0.04)    # 4% target
```

This uses **arbitrary percentages** instead of:
- ❌ Aggressive print cluster SL
- ❌ LVN-based SL
- ❌ VA boundary SL
- ❌ ATR-based SL

### 1.4 Session Risk Manager Not Enforced ❌❌

**What Fabio Says:**
> "3 consecutive losses = stop for the day. Max 5 trades per session."

**What the System Does:**
The `_max_trades_per_session` was reduced to 3, but:
- The `can_trade()` check is not called before every entry
- The user saw 30+ trades in one session, suggesting the cap is NOT being enforced
- The circuit breaker logic exists but isn't being triggered properly

**Evidence from trade log:**
```
CRUDEOIL 8900 SHORT x100 -3383.47 9:45:00 PM → 9:48:41 PM
CRUDEOIL 8900 LONG x35 +2075.45 9:40:00 PM → 9:48:10 PM
CRUDEOIL 8900 LONG x100 -452.00 9:35:00 PM → 9:43:43 PM
... (30+ trades in 2 hours)
```

This is **impossible** with a 3-trade session cap.

### 1.5 LLM Is Being Called Too Frequently ❌❌

**What Fabio Says:**
> "LLM enriches but never decides. Runs async, never blocks signal pipeline."

**What the System Does:**
- LLM is called on every tick (when conditions allow)
- Each LLM call can generate a signal
- The `trigger_llm` flag in `_on_tick()` fires `self._llm_handler.run_entry()`
- This creates an independent entry path that can execute trades

## 4. The Fix Required

### 4.1 Remove Signal Coordinator Entry Path ❌
The `SignalCoordinator.evaluate_entry()` method should be **removed** or **renamed to `evaluate_candidate`** and only used for UI display. It should NOT be used for actual trade execution.

### 4.2 Restore Single Entry Pipeline ❌
All entry decisions MUST flow through a single path:
```
Tick → AMT Analysis → 12-Gate Pipeline → TradeConstructor → Signal
```
No parallel paths, no scattered logic, no threading.

### 4.3 Enforce Drive 2 Requirement ❌
Every entry MUST check `drive_number == 2` and `drive_1_rejected == True`.

### 4.4 Fix Stop Loss ❌
SL must be calculated from:
- Aggressive print cluster + buffer
- LVN boundary + buffer
- VA boundary + buffer
NOT from arbitrary percentages.

### 4.5 Enforce Session Risk Cap ❌
`can_trade()` MUST be called before EVERY entry attempt. The 3-trade cap MUST be enforced.

### 4.6 Reduce LLM Call Frequency ❌
LLM should only be called:
- On new candle boundaries (not every tick)
- With a minimum 10s cooldown
- In advisory mode only (never for entry decisions)

## 5. Recommended Immediate Actions

1. **Disable Signal Coordinator entry path** — rename to `evaluate_candidate`, remove `should_enter` logic
2. **Restore single entry pipeline** — all entries through `run_gate_pipeline()` + `build_entry_signal()`
3. **Enforce `can_trade()` check** — add before every entry in `_on_tick()`
4. **Fix SL calculation** — use `sl_from_aggressive_print()` from `entry_gate.py`
5. **Reduce LLM frequency** — only on candle boundaries with 10s cooldown
6. **Run existing tests** — verify all 805 tests still pass
