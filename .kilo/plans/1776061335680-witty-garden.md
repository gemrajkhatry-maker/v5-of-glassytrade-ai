# Comprehensive Backend Architecture Improvement Plan

## Executive Summary

This document presents a detailed architectural analysis and refactoring plan for the backend trading system. The current codebase suffers from **significant architectural decay** including monolithic classes, tight coupling, lack of separation of concerns, and poor testability. The proposed refactoring will transform the system into a clean, modular, and maintainable architecture based on Hexagonal Architecture (Ports and Adapters) and Domain-Driven Design (DDD) principles.

### 1.2 Layer Analysis

#### **Domain Layer** (`app/domain/`)
**Intended**: Pure business logic, no infrastructure dependencies
**Reality**: Mixes infrastructure concerns with business logic

**Key Issues**:
- `AMTAnalyzer` (1200+ lines) does everything: volume profile, LVN/HVN, market state, aggression, signals, NPOC, drive, opening, MTF, acceptance/rejection, warmup, composite profile
- `OptionScannerService` (430 lines) mixes data fetching, filtering, scoring, selection
- `GatePipeline` (380 lines) complex decision logic with 12 gates
- `SignalCoordinator` (500+ lines) orchestrates multiple services

#### **Application Layer** (`app/application/`)
**Intended**: Orchestrate domain objects, coordinate workflows
**Reality**: Contains business logic that belongs in domain layer

**Key Issues**:
- `EntryCoordinator` and `ExitCoordinator` contain strategy logic
- `TickProcessor` mixes data processing with business rules
- `SessionStateManager` contains trading logic

#### **Infrastructure Layer** (`app/infrastructure/`)
**Intended**: Concrete implementations of ports
**Reality**: Leaking into domain layer through direct dependencies

**Key Issues**:
- Domain services directly import infrastructure adapters
- Configuration is scattered and not properly encapsulated
- No clear dependency injection

### 1.3 Code Quality Metrics

#### **Cyclomatic Complexity**
- `AMTAnalyzer.analyze()` - 45+ branches, 1200+ lines
- `OptionScannerService.scan_top_n()` - 35+ branches, 430 lines
- `GatePipeline.evaluate()` - 30+ branches, 380 lines

#### **Coupling Analysis**
- High coupling between services
- Circular dependencies between `AMTAnalyzer`, `SignalCoordinator`, `GatePipeline`
- Domain services depend on concrete infrastructure implementations

#### **Duplication**
- Volume profile calculation appears in multiple services
- Similar logic for LVN/HVN detection in different places
- Duplicate code for ATR, VWAP calculations

### 1.4 Architectural Issues Summary

| Issue | Severity | Impact |
|-------|----------|--------|
| Monolithic classes (AMTAnalyzer, OptionScannerService) | Critical | Hard to understand, test, maintain |
| Tight coupling between layers | Critical | Hard to test, modify, scale |
| Infrastructure leaks into domain | Critical | Violates separation of concerns |
| Lack of abstractions (ports/interfaces) | High | Hard to swap implementations |
| Configuration scattering | High | Hard to manage, test with different configs |
| Code duplication | Medium | Inconsistent behavior, harder to maintain |

```python
# app/dependency_injection/service_graph.py
class ServiceGraph:
    def __init__(self, config: Configuration):
        self._services: Dict[Type, Any] = {}
        self._adapters: Dict[Type, Any] = {}
        
        # Register adapters
        self.register_adapter(IMarketData, DhanMarketDataAdapter)
        self.register_adapter(IOptionChainFetcher, DhanOptionChainFetcher)
        self.register_adapter(IStorage, SQLiteStorageAdapter)
        self.register_adapter(ILLMInference, MLXInferenceAdapter)
        self.register_adapter(IProbabilityInference, LGBMProbabilityAdapter)
        
        # Initialize services
        self._initialize_services()
    
    def register_adapter(self, port: Type[T], implementation: Type[T]) -> None:
        self._adapters[port] = implementation
    
    def get(self, service_type: Type[T]) -> T:
        if service_type not in self._services:
            self._services[service_type] = self._create_service(service_type)
        return self._services[service_type]
```
